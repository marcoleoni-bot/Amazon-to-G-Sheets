When the planner comes back wrong

Thirty seconds of triage, then the three things to send.

1 · Triage — click one bad cell, read the formula bar

Formula bar showsVerdictWhere to look
A bare number, or blank No answer written The tab. Filter, protection, hidden rows.
A short formula you don't recognise No answer written — leftover The write was dropped; the old template's formula survived.
=IF($C8="",…) — long, starts with IF Wrong answer The rules. Read the Reason column beside it.
A formula containing #REF! Broken reference A named range was deleted. Re-run; it rebuilds them.

2 · Check the tab before blaming the code

Same code runs over all three lanes. If one tab is wrong and the others are right, the cause is on that tab.

  • Filter. Data → Remove filter. A filter hides rows, and a hidden row will not accept a write.
  • Hidden rows. Select all → right-click → unhide.
  • Protected range. Data → Protected sheets and ranges.
  • Stray content far below the data. Ctrl+↓ from a data column. If it lands on row 5741 when you have 491 SKUs, that is the problem.

The planner now clears filters and unhides rows itself before every write, and names them on the Run header. If you see something in that list, that is why.

3 · Send Claude

  1. The exact error text, whole. Not paraphrased — the list of column letters in it is the diagnosis.
  2. One formula copied from the formula bar of a bad cell.
  3. The file link.
  4. Which tabs are right and which are wrong.

Open with one sentence: "Tac > FBA has no formulas at all, the other two lanes are fine." That sentence is worth more than a page of description.

The three traps in this project

TrapLooks likeWhy
Filter on a tab Some rows calculated, most not — or none at all Writes skip rows a filter has hidden. Silently.
Named range deleted #REF! sitting inside otherwise-normal formulas Deleting a name rewrites every formula that used it, on the spot.
getLastRow() counting junk Formulas running thousands of rows past the data Stray cells far below the SKUs stretch the sheet's idea of "last row".

The one-line principle

An error tells you something failed. A silent no-op tells you nothing — so look for what did not change.
